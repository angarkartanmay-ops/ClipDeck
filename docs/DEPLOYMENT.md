# Deploying ClipDeck

A guide for IT administrators and for anyone installing ClipDeck on a company
laptop. ClipDeck keeps clipboard history on the device only: it makes no
network connections, needs no administrator rights to install or run, adds no
drivers, services or browser extensions, and can be managed with Group Policy,
Intune, a configuration profile or a policy file.

The policy templates mentioned below are in this repository's
[policy](../policy) folder and attached to each release as
`ClipDeck_<version>_policy-templates.zip`.

## For security reviewers

- **What it reads:** the clipboard, when its contents change, and the name of
  the app that copied. Nothing else on the screen or disk.
- **What it writes:** its own history folder (above), its settings file, a
  per-user start-at-login entry (Windows `HKCU\...\Run`, macOS
  `~/Library/LaunchAgents/com.tanmayangarkar.clipdeck.plist`, Linux
  `~/.config/autostart/clipdeck.desktop`) and the web view's cache.
- **No network access.** No telemetry, crash reports, update checks, accounts
  or sync. The dashboard's content security policy only allows the app's own
  bundled files, and on Windows the web view runs with background networking,
  component updates, SmartScreen and sync turned off. You can block ClipDeck
  in the firewall with no loss of function.
- **No keyboard hooks or input monitoring.** ClipDeck registers its own
  shortcuts with the operating system (`RegisterHotKey`, Carbon hot keys,
  `XGrabKey`); it never sees other keystrokes.
- **Privacy markers are honoured.** Copies flagged as private are never read
  past the flag: on Windows `ExcludeClipboardContentFromMonitorProcessing`,
  `CanIncludeInClipboardHistory = 0` and `Clipboard Viewer Ignore`; on macOS
  the `org.nspasteboard.ConcealedType`/`TransientType`/`AutoGeneratedType`
  conventions (and 1Password's own type); on Linux KDE's
  `x-kde-passwordManagerHint`. A per-app blocklist covers apps that don't flag
  their copies and ships with common password managers.
- **Respects the OS.** On Windows, if the "Allow Clipboard History" policy is
  off, ClipDeck stops recording unless you also set
  `allowWhenSystemHistoryDisabled`. On macOS, if the user has told the system
  not to let ClipDeck read the clipboard, it stops and says so.
- **Source and builds.** The source is public. Release files are built by
  GitHub Actions from a tagged commit
  ([build.yml](../.github/workflows/build.yml)) and listed with SHA-256
  checksums in `SHA256SUMS.txt`. Dependencies are permissively licensed and
  checked in CI ([THIRD_PARTY_LICENSES.md](../THIRD_PARTY_LICENSES.md)).

See also [SECURITY.md](../SECURITY.md) and [PRIVACY.md](../PRIVACY.md).

## Windows

### Which download

| File | Installs to | Admin | Use it for |
| --- | --- | --- | --- |
| `ClipDeck_<version>_x64-setup.exe`, `..._arm64-setup.exe` | `%LOCALAPPDATA%\ClipDeck` | No | Individual installs, Intune user-context Win32 apps |
| `ClipDeck_<version>_x64_en-US.msi` | `C:\Program Files\ClipDeck` | Yes | Intune line-of-business apps, Configuration Manager, GPO software installation |
| `ClipDeck_<version>_x64_portable.zip`, `..._arm64_portable.zip` | Wherever it is unzipped | No | Trying it out, machines where installers are blocked |

Silent install and removal:

```powershell
# Per-user installer
.\ClipDeck_0.1.1_x64-setup.exe /S
& "$env:LOCALAPPDATA\ClipDeck\uninstall.exe" /S

# Per-machine MSI
msiexec /i ClipDeck_0.1.1_x64_en-US.msi /qn /norestart
msiexec /x ClipDeck_0.1.1_x64_en-US.msi /qn
```

Detection rules: `%LOCALAPPDATA%\ClipDeck\clipdeck.exe` (per-user) or the MSI
product code (per-machine). Each user's history and settings stay in their own
profile and are not removed on uninstall.

### WebView2

ClipDeck draws its window with Microsoft Edge WebView2, which is part of
Windows 11 and is installed on almost every up-to-date Windows 10 PC. If it is
missing, the installer downloads Microsoft's WebView2 bootstrapper, which is
the only network access during installation (made by Microsoft's installer,
not by ClipDeck). On offline or tightly firewalled machines, deploy the
**WebView2 Evergreen Standalone Installer** from Microsoft first.

### SmartScreen, Smart App Control and signing

Signed releases show the publisher **Tanmay Angarkar** and start normally.
When a release is not code-signed (check the file's Properties › Digital
Signatures), Windows reacts as follows:

- **SmartScreen** shows "Windows protected your PC": choose **More info ›
  Run anyway** after checking the checksum.
- **Smart App Control** (Windows 11, when on) blocks unsigned apps outright;
  use a signed release.
- Antivirus products that score files by reputation may also be cautious with
  a new unsigned release.

```powershell
Get-FileHash .\ClipDeck_0.1.1_x64-setup.exe -Algorithm SHA256   # compare with SHA256SUMS.txt
Get-AuthenticodeSignature .\ClipDeck_0.1.1_x64-setup.exe          # signer, if signed
```

### AppLocker and App Control for Business (WDAC)

- AppLocker's default rules only allow programs in `Program Files` and
  `Windows`, so the per-user installer will be blocked: deploy the **MSI**.
- For signed releases, allow ClipDeck with a **publisher rule** (publisher
  "Tanmay Angarkar", product "ClipDeck"); it keeps working across updates.
- For unsigned releases, use a **hash rule** for `clipdeck.exe`, which must be
  updated with each release. Avoid path rules for user-writable folders.

### Settings by Group Policy or Intune

1. Copy `policy/windows/ClipDeck.admx` to `C:\Windows\PolicyDefinitions` (or
   your domain's central store) and `policy/windows/en-US/ClipDeck.adml` to its
   `en-US` folder.
2. The settings appear under **Computer Configuration** and **User
   Configuration › Administrative Templates › ClipDeck**. Computer settings win.
3. In Intune, import the same files under **Devices › Configuration › Import
   ADMX**, then create a profile from **Templates › Imported Administrative
   templates**. Alternatively, write the registry values below with a
   remediation script.

The policy is read when ClipDeck starts. Managed settings show a **Managed**
badge in ClipDeck and cannot be changed by the user.

Windows' own policy **Allow Clipboard History** (Computer Configuration ›
Administrative Templates › System › OS Policies) is honoured: when it is
Disabled, ClipDeck stops recording and explains why, unless
`allowWhenSystemHistoryDisabled` is set. Unlike the Windows clipboard,
ClipDeck never syncs to the cloud.

## macOS

### Installing

Open `ClipDeck_<version>_universal.dmg` and drag ClipDeck to **Applications**.
Without an administrator password, drag it to **Applications** in your home
folder (`~/Applications`; create it if needed). ClipDeck lives in the menu bar
and has no Dock icon.

For MDM deployment, use the `.dmg` or the `.app.zip` (Jamf Pro, Kandji,
Mosyle). For tools that require a package, wrap the app and sign the package
with your own Developer ID Installer certificate:

```bash
pkgbuild --component /path/to/ClipDeck.app --install-location /Applications \
  --sign "Developer ID Installer: Your Org (TEAMID)" ClipDeck.pkg
```

### Gatekeeper

Releases signed with a Developer ID and notarized by Apple open normally. A
release without a Developer ID signature (`codesign -dv ClipDeck.app` shows
`Signature=adhoc`) is blocked on first launch: open **System Settings ›
Privacy & Security** and choose **Open Anyway** (on macOS 15 and later,
Control-clicking the app no longer offers this). Managed Macs may not allow
it; deploy a signed release or approve it through your MDM.

### Permissions

- **Accessibility** (optional). With it, choosing a clip pastes it into the
  app you were using; without it, choosing a clip copies it and you press ⌘V.
  ClipDeck shows a notice with an **Allow** button that opens the right
  settings pane. Turning it on requires an administrator. On managed Macs,
  approve it with the PPPC payload in
  [ClipDeck.mobileconfig](../policy/macos/ClipDeck.mobileconfig) (Developer
  ID-signed builds only; macOS ties the approval to the signing identity).
- **Paste from Other Apps** (newer macOS). macOS can ask before an app reads
  the clipboard in the background. If ClipDeck isn't allowed, it stops
  recording and shows a notice; set ClipDeck to **Allow** in **System
  Settings › Privacy & Security › Paste from Other Apps**. Apple does not
  offer an MDM setting for this yet.
- No Input Monitoring, Screen Recording, Full Disk Access or network
  permissions are needed.

### Settings by configuration profile

Edit [policy/macos/ClipDeck.mobileconfig](../policy/macos/ClipDeck.mobileconfig)
and upload it to your MDM, or upload just the settings as a custom
preference domain `com.tanmayangarkar.clipdeck` (Jamf: Application & Custom
Settings; Intune: Preference file). Every key in that domain is enforced and
shown locked; keys use the names and types in the table below (booleans,
integers, strings, arrays of strings). The blocklist takes app bundle IDs,
such as `com.bitwarden.desktop`.

The profile also approves ClipDeck's **Open at Login** agent
(`com.tanmayangarkar.clipdeck`) so users don't get a "Background Items Added"
notification. Remove that payload if users should be able to turn it off.

## Linux

### Installing

```bash
sudo apt install ./ClipDeck_0.1.1_amd64.deb        # Debian, Ubuntu
sudo dnf install ./ClipDeck-0.1.1-1.x86_64.rpm     # Fedora, RHEL, openSUSE (zypper)
chmod +x ClipDeck_0.1.1_amd64.AppImage && ./ClipDeck_0.1.1_amd64.AppImage   # no root
```

The packages are named `clip-deck` (`sudo apt remove clip-deck`). Builds
target Ubuntu 22.04 or newer and equivalents (glibc 2.35+). If the AppImage
doesn't start because FUSE 2 is missing, run it with
`--appimage-extract-and-run`.

### Desktop notes

- **Wayland** doesn't let apps grab global shortcuts. Add a custom shortcut
  in your desktop's keyboard settings that runs `clipdeck --toggle` (or the
  AppImage's path with `--toggle`). ClipDeck needs XWayland (standard on
  GNOME and KDE) to watch the clipboard.
- Choosing a clip **copies** it; press Ctrl+V to paste. Linux desktops don't
  let one app type into another.
- History is not encrypted by ClipDeck on Linux; the folder is readable only
  by its owner. Use full-disk encryption, as most managed fleets already do.

### Settings by policy file

Create `/etc/clipdeck/policy.json` (owned by root, mode 0644) with any of the
keys below, for example [policy/linux/policy.json](../policy/linux/policy.json).
Blocklist entries are program names such as `keepassxc`.

## Policy reference

The same keys work on every platform. On Windows, booleans and numbers are
`REG_DWORD` values and lists are `REG_MULTI_SZ` (or `REG_SZ` separated by
`;`). Keys that are not set stay under the user's control.

| Key | Type | Values (default) | Effect |
| --- | --- | --- | --- |
| `disableCapture` | boolean | (off) | Record nothing on this device. Earlier clips stay until they expire or are deleted. |
| `allowWhenSystemHistoryDisabled` | boolean | (off) | Windows: keep recording when the "Allow Clipboard History" policy is off. |
| `captureImages` | boolean | (on) | Record copied images. |
| `captureFiles` | boolean | (on) | Record copied file lists (paths, not file contents). |
| `captureRich` | boolean | (on) | Keep HTML/RTF formatting alongside plain text. |
| `blocklist` | list of strings | password managers | Apps whose copies are never recorded: executable names (Windows), bundle IDs (macOS), program names (Linux). Replaces the user's list. |
| `encrypt` | boolean | (off) | Encrypt stored history (Windows and macOS). Existing history is converted at the next start. |
| `retentionDays` | integer | 0–3650 (0) | Delete clips older than this many days. Set by policy, this includes pinned clips. 0 = no age limit. |
| `clearOnExit` | boolean | (off) | Delete unpinned clips when ClipDeck quits or the user signs out. |
| `historyLimit` | integer | 10–200 (50) | Unpinned clips kept; the oldest go first. |
| `maxDiskMb` | integer | 50–10000 (500) | Disk budget for history, in MB. |
| `maxItemMb` | integer | 1–512 (64) | Larger copies are not recorded. |
| `autostart` | boolean | (on) | Start at sign-in. |
| `pasteOnSelect` | boolean | (on) | Paste into the previous app after choosing a clip (otherwise only copy). |
| `restoreClipboard` | boolean | (off) | Put the previous clipboard contents back after pasting. |
| `keepDashboardWarm` | boolean | (off) | Keep the dashboard loaded for instant opening (~120 MB more memory). |
| `hotkeyDashboard`, `hotkeyQueue` | string | e.g. `Ctrl+Shift+V` | Shortcuts for the dashboard and the paste queue. |
| `slotModifiers` | string | e.g. `Ctrl+Alt` | Modifiers for the 1–9 paste slots; empty turns them off. |
| `displayMode` | string | `fullscreen`, `window` | How the dashboard opens. |
| `reduceMotion` | string | `system`, `on`, `off` | Animation level. |

Out-of-range numbers are clamped and values of the wrong type are ignored.

## Removing ClipDeck and its data

| | Uninstall | Delete history and settings |
| --- | --- | --- |
| Windows | Settings › Apps, or the commands above | `%APPDATA%\ClipDeck`, `%LOCALAPPDATA%\com.tanmayangarkar.clipdeck` |
| macOS | Quit from the menu bar, delete ClipDeck.app | `~/Library/Application Support/ClipDeck`, `~/Library/LaunchAgents/com.tanmayangarkar.clipdeck.plist`, `~/Library/WebKit/com.tanmayangarkar.clipdeck`, `~/Library/Caches/com.tanmayangarkar.clipdeck`, Keychain item `com.tanmayangarkar.clipdeck` |
| Linux | `sudo apt remove clip-deck`, `sudo dnf remove clip-deck`, or delete the AppImage | `~/.local/share/clipdeck`, `~/.local/share/com.tanmayangarkar.clipdeck`, `~/.config/autostart/clipdeck.desktop` |
