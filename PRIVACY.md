# Privacy

ClipDeck is designed so that your clipboard never leaves your device.

## What ClipDeck stores

- Items you copy (text, rich text/HTML, RTF, images and file lists),
  the name of the app they came from, and when they were copied.
- Image thumbnails generated from copied images.
- Your settings.

Everything is stored locally, in a folder only your user account can read:

| Windows | macOS | Linux |
| --- | --- | --- |
| `%APPDATA%\ClipDeck\` | `~/Library/Application Support/ClipDeck/` | `~/.local/share/clipdeck/` (or `$XDG_DATA_HOME/clipdeck`) |

| Path | Contents |
| --- | --- |
| `clipdeck.db` | SQLite metadata and short text previews used for search |
| `blobs/` | The full copied data, one file per item |
| `thumbs/` | Thumbnails of image items |
| `settings.json` | Your settings |

The deck's web view also keeps its normal browser cache, which contains no
clipboard data beyond what was shown on screen: `%LOCALAPPDATA%\com.tanmayangarkar.clipdeck\`
on Windows, `~/Library/WebKit/` and `~/Library/Caches/` (under
`com.tanmayangarkar.clipdeck`) on macOS, and
`~/.local/share/com.tanmayangarkar.clipdeck/` on Linux.

## What ClipDeck does not do

- **No network access.** ClipDeck makes no network connections: no
  telemetry, analytics, crash reporting, update checks or cloud sync. The
  dashboard's content security policy blocks all remote content.
- No accounts and no third-party services.
- It does not read other apps' windows, files or keystrokes. It reads the
  clipboard when it changes, and the name of the app that copied.

## Protecting sensitive data

- **Copies that apps mark as private are never captured.** Password managers
  mark their copies this way. ClipDeck honours:
  - Windows: the clipboard formats `ExcludeClipboardContentFromMonitorProcessing`,
    `CanIncludeInClipboardHistory` (value 0) and `Clipboard Viewer Ignore`;
  - macOS: the `org.nspasteboard.ConcealedType`, `TransientType` and
    `AutoGeneratedType` markers, and 1Password's own type;
  - Linux: KDE's `x-kde-passwordManagerHint`.
- **Blocklist** (Settings › Privacy): copies from listed apps are skipped.
  It ships with common password managers on every platform.
- **Pause capture** in the tray/menu bar or the deck stops recording entirely.
- **Encrypt history on disk** protects stored items and thumbnails so only
  your user account can read them: with Windows DPAPI, or on macOS with a
  random key kept in your login Keychain (ChaCha20-Poly1305). Not available
  on Linux, where full-disk encryption is the recommended protection.
- **Delete clips after** a number of days removes older unpinned clips
  automatically.
- **Clear history on exit and sign-out** deletes unpinned items when
  ClipDeck quits or you sign out.
- Deleted items are removed from disk, and the database runs with
  `secure_delete` so deleted previews are overwritten.
- On a managed device, your organization may enforce some of these settings
  (shown with a **Managed** badge) or turn capture off. Policies are read
  from the device; ClipDeck reports nothing back. See
  [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).

**Warning:** a clipboard history may contain passwords, personal messages
or other sensitive data you copied. Anyone who can sign in to your user
account can open ClipDeck and see it. Use the privacy options above, pin
only what you need, and clear the history when sharing a computer.

## Removing all data

Quit ClipDeck from the tray or menu bar, then delete the data folder listed
above (and the web view cache, if you like). On macOS, also delete the
Keychain item `com.tanmayangarkar.clipdeck` if you used encryption.
Uninstalling does not delete your history automatically.
